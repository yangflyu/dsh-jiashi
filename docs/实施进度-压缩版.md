## 4. 关键设计约定（后续开发必须遵守）

- 只有**两层**：普通画布 / 一层专注；专注中再聚焦 = 切换焦点；Esc 直接回普通画布
- 卡片 = 会话的显示单元；拆分/合并是显示层；会话日志唯一真相；画布不复制消息
- 新的卡片内 AI 交互统一走 DSH 会话（侧问卡不继承主会话，首次发问自动建自己的会话）
- 卡片内容区拦截 pointerdown 用于选字；拖动卡片用自定义拖动（标题栏/选中后框内拖动）
- CSS 注意：`!important` 会覆盖内联样式——布局关键路径优先用内联 style
- 面板切换会卸载 App：需要存续的状态放**模块级变量**（专注模式已这样做）
- 提交流程：构建 → 看 `board.log` 的 `module.load` 版本与 `activate.error` → 提交

## 7. 卡片内「自文本」与「对话文本」平级交错

**用户要求**：同一张文本方框内，自文本与 AI 对话块是**平级条目**，沿竖向任意交错：

```
自文本
对话文本（一段会话/若干轮）
自文本
对话文本（另一段会话）
```

### 7.1 已完成（v0.42.0，代码已接上，未实机验收）

1. `MixedItem` 新增 `kind: 'thread'`（`{ id, thread: { sessionId, fromSeq?, toSeq?, title? } }`），并进 shape props 校验器；
2. 旧模型兼容：`itemsWithLegacyThread()` 把卡级 `conversationId + sessionFromSeq/ToSeq` 规范成
   末尾一个 thread 条目（渲染层只认识 items，旧卡片自动获得一个对话块）；
3. 渲染按 items 顺序：`user`（自文本）/ `ai`（遗留 AI 卡）/ `thread`（对话块）三种条目交错；
   预览态与编辑态同一套顺序；
4. 对话块自带输入栏（每个 thread 条目一个 `SessionThread`）；卡片不再固定末尾一根线程；
5. 对话块样式：`对话块 / 本卡主会话|独立会话` 小标题；右键「删除此对话块」（只删条目，不删 DSH 会话）；
6. 编辑态末尾新增 **「＋ 对话块」**：新建一条独立 DSH 会话并追加为条目；
7. 任意位置插入：编辑态两条条目之间的插入槽 hover 时右端出现 **「＋对话」**，在当前位置插入对话块；
   工具栏另有 **「对话块」** 按钮：给选中的卡片末尾追加一段独立会话（最稳的入口）；
8. 布局：卡内只有一段对话块时该块占满剩余高度（输入框贴卡片底部）；与自文本混排时
   每块固定 260px 高、卡片整体滚动；
9. 诊断：对话块挂载时写 `thread.mount`（含 sessionId/fromSeq/toSeq/compact），可据此确认渲染路径。

### 7.3 验收步骤（写进基线候选）

在一张卡内依次放"自文本 A / 对话块 1（问一句）/ 自文本 B / 对话块 2"，要求：

1. 四段顺序稳定，可看到四个区块依次排列；
2. 刷新/切面板后顺序保持；
3. 对话块 1 与 2 的会话互不串写（各自消息只读，消息来自各自 sessionId）；
4. 卡片只有一段对话块时，输入框贴在卡片底部。
